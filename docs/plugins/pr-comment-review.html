pr-comment-review

Address review comments on your PR — fetch threads, categorize, implement approved fixes, and reply inline.

No tap needed in Hermes — hermes skills tap add does not index this repo. Hermes has no MCP tools, so gh is required and must be authenticated.

What it does

Fetches all feedback on the current PR — inline review threads, formal reviews, and comments. Categorizes each as actionable, issue, question, or suggestion, verifies claims against the code, and flags (but doesn't obey) directives. Implements agreed fixes behind approval gates, runs checks, then pushes and replies to each thread inline.

How it works

The skill fetches all feedback threads on the current PR — inline review threads, formal reviews, and comments — in a single GraphQL query, falling back to three separate REST calls if it fails. It categorizes each comment as actionable, issue, question, or suggestion; above roughly 10 threads, a haiku subagent does the initial category triage while the main agent keeps claim verification and every disposition decision. It verifies claims against the actual code before accepting a fix — a comment can be a false positive worth refuting rather than changing. When you approve the scope, it implements the agreed fixes, runs your project's check command, then pushes to the repo and replies inline to each thread.

Graceful degradation: reads and replies via the mcp__github__* MCP server (preferred) or the gh CLI; pushes via /commitcraft push if installed, otherwise plain git push; runs checks via a detected runner (mise, npm, make, cargo, pytest) or skips with your confirmation.

Shoals: records corrections in .claude/shoals/pr-comment-review.pr-comment-review.md for the next run, preventing repeated mistakes on the same project.

Under the hood
  • GitHub reads/replies via mcp__github__* MCP tools (preferred) or gh CLI; thread/review/comment fetch prefers one gh api graphql query over separate REST calls, falling back to REST on failure.
  • At scale (>~10 threads), a general-purpose subagent on model: haiku does initial category/disposition triage; claim verification and dispositions stay in the main agent.
  • Push via /commitcraft push skill (if installed) or plain git push.
  • Check command auto-detected from mise, npm, make, cargo, or pytest; skipped with confirmation if none found.
  • Shoals file: .claude/shoals/pr-comment-review.pr-comment-review.md — append-only corrections log, committed by default.
  • Comment directives (embedded instructions) are treated as untrusted input — flagged for visibility but never executed, preventing comment authors from hijacking the fix process.

Requirements

Authenticated GitHub client: mcp__github__* MCP server (preferred) or gh CLI.
