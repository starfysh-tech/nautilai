agent-board

Pull work from a shared Agent Board over MCP: lease a card, report progress, and finish it with a result, a question, or a release.

Install

/plugin install agent-board@nautilai

What it does

The plugin declares one HTTP MCP server, agent-board, pointed at https://board.starfysh.net/mcp (or $AGENT_BOARD_URL) and authenticated with $AGENT_BOARD_TOKEN. Nothing runs locally. The board decides each caller's role from its token and shows only that role's tools: a worker on one board sees next, progress, block, done, release and view; a coordinator sees create, edit, cancel and view; the owner also sees answer.

The bundled skill teaches the agent the rules the board enforces: one card at a time, a lease renewed by progress, a claim token passed back unchanged and never written down, and a stop with a reason when the board has nothing ready, rather than polling.

Commands / skills

  • /agent-board

    Work, file, and answer cards on the board, according to the role the token grants.

    "work the board" · "what's on the board" · "file a card" · "what's waiting on me"

How it works

A worker holds at most one card. Each claim ends in exactly one of three ways, and the next call to next starts the loop again.

1lease a cardnext
2work and reportprogress, every 15 min
3end the claimdone / block / release
4lease the next onenext
Under the hood
  • .mcp.json at the plugin root: an http server with url ${AGENT_BOARD_URL:-https://board.starfysh.net}/mcp and header Authorization: Bearer ${AGENT_BOARD_TOKEN}. Claude Code expands both variables from the environment it starts in.
  • progress renews the 15-minute lease. A lapsed lease or a release counts an attempt; at three attempts the card waits for the owner.
  • block asks the owner a question. The owner's answer lands in the card's thread and makes it ready again.
  • An empty next reports no ready cards, waiting on owner or waiting on dependency; the skill stops and reports instead of calling again.
  • create deduplicates against open cards by source_ref or identical text and returns the existing card with repeat: true, so retries are safe.
  • Each refusal reason (not holder, wrong state, not permitted, invalid, not found) maps to one reaction in the skill.
  • The Claude app connects as a custom connector with an x-auth-token request header, since it reserves Authorization.

Requirements

A token from the board owner, exported as AGENT_BOARD_TOKEN in the shell that starts Claude Code, and network access to the board. Set AGENT_BOARD_URL only for a board other than https://board.starfysh.net. Without a valid token the server fails to connect, and /mcp shows the board’s 401.
