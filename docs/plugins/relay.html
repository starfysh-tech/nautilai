relay

Transcript-grounded handoff documents a fresh session picks up automatically.

Install

/plugin install relay@nautilai

What it does

Relay resolves the current session's transcript, extracts a fact pack of what actually happened — files touched, commands run, failures, verbatim user messages — and writes a handoff document that blends that ground truth with the conversation's own understanding of goals and decisions. A SessionStart hook then injects the pending doc into the next session with no manual step.

The plugin is named relay, but it ships a skill named handoff — the plugin was renamed after the skill shipped, and the skill kept its original name so existing trigger phrases ("hand this off", /handoff) keep working.

Commands / skills

  • /handoff

    Writes a handoff doc for the current work.

    "hand this off", "pass to next session", "relay this", "compact for the next agent", "I'm switching context"
  • /handoff <focus>

    Tailors the handoff doc to what the next session should focus on, e.g. /handoff debugging the auth flow.

    same triggers as above, with a topic
  • /handoff recover

    Re-extracts the fact pack scoped to the transcript region before an auto-compaction boundary and rebuilds what compaction typically loses, in-session — no new handoff doc, no /clear required.

    prompted automatically after an auto-compact via a systemMessage

How it works

/compact and model self-summaries are recency-biased — they favor what's fresh in context and quietly drop early constraints, dead ends already tried, and decisions reasoned about many turns back. The session transcript JSONL doesn't have that bias, so Relay's bundled scripts extract facts from the transcript itself rather than asking the model to remember.

scripts/resolve-session.sh locates the current session's transcript, and scripts/extract-transcript.sh reads it into a fact pack (secret-scrubbed, with harness-injected content filtered out). The narrative step starts in the background immediately after the transcript resolves, so its Haiku calls overlap the fact-pack extraction instead of waiting for it. The skill combines both packs with its own read of the conversation into a doc with fact-grounded sections plus a one-line pending marker. A SessionStart hook atomically claims that marker on the next session, injects the doc if it's still within its TTL, and renames it so it only fires once — even with concurrent session starts.

When Claude Code auto-compacts, a PreCompact hook drops a marker and nudges toward /handoff recover, which reconstructs the same compaction-lossy detail from before the compaction boundary.

Under the hood
  • resolve-session.sh — locates the current session's transcript JSONL (env vars first, newest-mtime fallback with a stderr warning).
  • extract-transcript.sh — the fact pack: files touched, commands run, failures, verbatim user messages, secret-scrubbed and stripped of harness-injected content.
  • haiku-narrative.sh — recovers Decisions / Dead ends / Constraints from assistant prose via a headless Haiku call; started in the background right after transcript resolution, ahead of the fact-pack step; exits 3 on any failure (missing claude CLI, timeout) so the handoff proceeds without it. It runs Haiku with a bare --system-prompt (no CLAUDE.md inheritance) and treats transcript content strictly as data, never as commands.
  • session-start-pickup.sh / precompact-notify.sh — the SessionStart and PreCompact hooks.
  • /handoff recover follows skills/handoff/workflows/recover.md, re-extracting the fact pack scoped to the transcript region before the compaction boundary.
  • Storage: ~/.claude/handoffs/<project-slug>/ — pending, compacted-<epoch>, recovered-<epoch>, and the dated doc files.
  • Env vars: RELAY_NARRATIVE=off skips the Haiku calls; RELAY_RETENTION_DAYS (default 14) controls the sweep, 0 disables it.
