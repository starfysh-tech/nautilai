phi-scan

Find Protected Health Information in your repo, then apply AI judgment to separate real exposure from noise.

Install

/plugin install phi-scan@nautilai

What it does

Scans your repo for Protected Health Information under the HIPAA Safe Harbor standard: SSNs, emails, phones, IPv4 addresses, US/ISO dates, and 5-digit ZIPs (with 17 restricted prefixes prioritized). A bundled phi_check.py scanner filters test data and honors inline suppressions. Then AI triage separates real exposure from noise, catching names and medical record numbers that regex misses. Optionally runs Django/React OWASP grep checks (off by default, stack-gated).

Under the hood
  • phi_check.py — matches HIPAA Safe Harbor patterns (SSN, email, phone, IPv4, US/ISO dates, 5-digit ZIPs); a ZIP in one of the 17 restricted prefixes is reported as zip_5(restricted), higher priority than an ordinary ZIP match.
  • Filters test data markers (test, mock, @example.com, 123-45-6789) and respects inline # phi-safe / // phi-safe suppressions.
  • Exits non-zero on real findings (doubles as a git pre-commit hook).
  • AI triage: reads flagged files to judge context, dismiss config/test/comment matches, catch names and medical record numbers; findings spanning more than ~5 files fan out to parallel general-purpose subagents on Haiku, one per file or small batch, synthesized afterward.
  • Optional PreToolUse write guard (hooks/hooks.json → scripts/phi_guard.py): scans Write/Edit/MultiEdit content before it lands on disk and cancels the call on a real PHI match; off by default, enabled per shell via PHI_SCAN_GUARD=1; fails open on a malformed payload or scanner error.
  • OWASP layer (off by default, Django/React only): runs shallow grep heuristics for hardcoded secrets, raw-SQL injection, mark_safe/innerHTML XSS, PHI/secrets in logs — not a real SAST; pair with semgrep/bandit for serious work.

Requirements

python3 on your PATH (stdlib-only, Python 3.10+).
