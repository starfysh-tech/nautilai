rbac-django

Audit Django/DRF code for authorization gaps, threat-model findings into abuse cases, then generate remediation playbooks.

Install

/plugin install rbac-django@nautilai

What it does

Three skills form a security workflow: the audit scans for missing permission classes, tenant-isolation leaks, IDOR, and write-side authorization gaps via AST and file analysis; the threat-model translates findings into ranked attacker abuse cases using PACE framework and BIL scoring; the remediation skill generates prioritized playbooks with test scaffolds and GitHub issues using project-discovered patterns, requiring explicit user approval before proposing fixes.

Commands / skills

  • /rbac-audit-django

    Scan a Django/DRF + React codebase for authorization gaps and generate a severity-ranked findings report with file:line citations.

    explicit slash form only
  • /rbac-threat-model

    Generate 5–10 ranked attacker abuse cases from audit findings using PACE framework (Principals, Assets, Channels, Escalation) and BIL scoring.

    explicit slash form only
  • /rbac-remediation-playbooks

    Generate prioritized remediation playbooks with test scaffolds and ready-to-paste GitHub issues, using the project's discovered patterns. User-invoked only; no auto-fix of authorization logic.

    explicit slash form only

How it works

The three skills form a sequential security audit pipeline: the first detects authorization gaps via AST and file-walk analysis; the second translates findings into ranked attacker abuse cases; the third proposes remediation without self-editing code.

1scan & audit
2threat-model
3generate playbooks
Under the hood
  • /rbac-audit-django — self-discovers role names, sensitive-data mixins, through-models; uses AST and file-walk for deterministic analysis (infers data structures from your code rather than hardcoding assumptions); reports findings with file:line citations, severity-ranked (disposition: report). Permission-class and @api_view detection each have a stdlib AST fallback when ast-grep is absent; view-file matching covers views.py, api.py, viewsets.py, and any file under a views/ package; tenant-isolation checks recognize scoping params named user, clinic, organization, tenant, study, team, workspace, account, or company.
  • /rbac-threat-model — generates 5–10 ranked abuse cases via PACE framework (Principals, Assets, Channels, Escalation) and BIL scoring; operates like an attacker with a valid account (disposition: report).
  • /rbac-remediation-playbooks — proposes fixes using project-discovered patterns; never edits code directly; no authorization gap is ever auto-fixed (findings are always report or ask-user); user-invoked only (disposition: ask-user). Playbooks and GitHub-issue bodies populate from templates/playbook.md and templates/github-issue.md.
  • Optional tools: ast-grep and ripgrep for faster structural analysis; degrades to stdlib AST/file-walk if absent.
  • Storage: docs/rbac-audit/report.md, rbac-audit-findings.json, threat-model.md, remediation-{now,next,later}.md.
  • Shoals: .claude/shoals/rbac-django.<skill>.md — append-only behavioral corrections.

Requirements

ast-grep and ripgrep (rg) are preferred for faster structural analysis but optional. If either is absent, the scanner degrades gracefully to stdlib AST and file-walk analysis with reduced coverage reported upfront.
